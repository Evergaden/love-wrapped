# Wrapped 纪念册

一个人填写的纪念册小程序。没有后端，也没有账号，你写下的内容只存在这台设备的本地缓存里。

写下两个昵称、在一起的日子，以及一些愿意记得的小事。然后左右滑动，翻一本只印了一份的小册子。翻到愿意留下的那一页，可以把它画成图片存进相册，也可以整本转发给对方——**对方点开就能看到你写好的那一册**。

> **为什么界面上的名字不是「恋爱Wrapped」？**
> 个人主体上架时类目只能选「工具」，名称和首屏文案里出现「恋爱」容易被判成
> 社交/婚恋类服务而驳回（这是个人主体最常见的驳回原因之一）。所以界面统一叫
> 「Wrapped 纪念册」，全部文案只在一处定义：`utils/brand.js`，想改回只改那一个文件。
> 后台注册的小程序名称请保持同一口径。

## 你会看到什么

填写页 11 项，其中 3 项必填：

1. 你的昵称、TA 的昵称、在一起的日子（必填）
2. 第一次约会的地方
3. 现在住的城市，和一起去过的地方——一个一个加成小气泡（最多八块），纪念册拼成一页，标出每块离现居地多远
4. 一起吃饭的频率（估「≈ N 顿」），和你们最爱吃的东西——数字页会写一行「永远 爱吃 …」
5. 吵架次数，以及谁先道歉（可整项留空）
6. 口头禅
7. 一件难忘的小事（结尾页会记下「写于」的日子和那天的第 N 天）
8. 异地还是同城；异地写两座城市，中间隔着多少公里自动算出来；同城选个见面频率（可整项留空）
9. 想对 TA 说的一句话

写完的一册可以「备份成文字」复制进微信收藏长久保存；礼物转发来的册子也能一键「收下」留在手机里。

外加一组「挑一套配色」：奶油（默认）、抹茶、晴蓝、雾紫四套主题。
主题影响整本纪念册、导出的图片和转发卡片封面，存在本机随时可换。

纪念册固定 6 页，顺序是在讲一件事，和问卷顺序不一样，每页有自己专属的排版：

1. 封面——两个名字并肩，天数压在胶囊里
2. 数字——一张张小卡排下来，末尾预告下一个整百天或周年
3. 起点——一张明信片，日期缩成右上角的邮戳
4. 去过的地方——一页拼图，一块一块歪着拼，最远的那块挂「最远」
5. 口头禅——那句话装在一只气泡里
6. 一件小事——一页手记，左侧一道色条，正文首行缩进
7. 结尾——整页居中的终章，像扉页的题字

填了「异地 / 同城」会在去过的地方后面多一张「旅程图」：异地是推算出来的公里数压在虚线上，同城是估出来的见面次数，下面都写着「0 公里，想见就能见到」这类温柔话；填了吵架次数或谁先道歉，会在口头禅后多一页（普通排版）。都留空就是 6 页。

没填的项会用安静的普通排版放一句占位的话，翻起来不缺页。屏幕和导出图用同一套排版，`utils/slides.js` 里写 `layout`，`pages/wrapped` 管屏幕，`utils/poster.js` 管图片，改排版两边都要跟上。

点「填入一组示例」会放上示例内容，含吵架、异地和几处地方，所以是 9 页。

纪念册页底部 dock 有一排配色圆点，翻着翻着也能直接换主题。

## 用微信开发者工具打开

1. 安装稳定版微信开发者工具：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 打开工具，用手机微信扫码登录。
3. 选择「小程序」，不要选「小游戏」。
4. 点「+」或「导入」。
5. 目录选**这一层**：文件夹里能直接看到 `app.json`。不要选到它的上一级，也不要只选中 `pages`。
6. AppID：填你自己的小程序 AppID。`project.config.json` 里的 `appid` 也需要同步换成同一个。
7. 如果问云开发或云服务，选「不使用」。
8. 确定之后，左侧模拟器应出现「Wrapped 纪念册」。

### 在模拟器里走一遍

1. 点「挑一套配色」里的任一套，整页颜色会立即跟着换。
2. 点「填入一组示例」。
3. 滑到下面，点「生成纪念册」。
4. 在纪念册上按住鼠标向左拖翻页。左下角有页码，第一页写着「向左滑」。
5. 点 dock 上的配色圆点，整本马上换色。
6. 点「导出此页」。稍等，底部弹出预览，导出的图片用的就是当前配色。
7. 点「查看大图」「直接发送给朋友」，或「存到相册」（模拟器常失败，见「已知限制」）。
8. 点「导出整本」会把整本画成一张**连贯的长图**：一张卡从头贯到尾，弥散光顺着长条流下去，节与节之间一道居中的短线，落款只在末尾出现一次。
9. 点「分享给 TA」转发给好友。转发卡片封面是专门画的 5:4 信纸；**对方点开卡片，直接看到你写好的整册**（答案装在链接里，从你的手机直达 TA 的手机）。

改答案：点左上角返回，改完再点「生成纪念册」。字是边写边存的。

## 隐私与用户信息

这个小程序**不联网、不登录、不收集任何信息**。

- 收集范围：只有你自己在填写页输入的昵称、日期和几件小事。
- 存储位置：全部在这台设备的本地缓存里，两个键名：答案 `loveWrapped.answers.v1`、主题 `loveWrapped.theme.v1`。不上传，不经过服务器，也没有云数据库。
- 转发：点「分享」时，你的答案会被压缩成一小段字符附在你发出的转发消息里，从你的手机直接送达对方的手机，中间只经过微信自己的转发通道，不落地、不经过任何服务器。对方看到的是一份只读的礼物：可以翻看、换配色、导出图片、继续转发，但不会写进 TA 自己的存储。没有你发起的转发，这些字哪儿也不去。
- 清除：填写页底部「清空这台设备上的答案」，或微信「设置 → 通用 → 存储空间 → 清除缓存」。
- 换设备 / 卸载：这些字会跟着消失，无法找回。

### 代码里的隐私适配

- `app.json` 已开启 `__usePrivacyCheck__`。
- `utils/privacy.js` 封装了 `wx.getPrivacySetting` 和 `wx.requirePrivacyAuthorize`，两个页面进页时都会查一次。
- 基础库低于 2.32.3 时这些接口不存在，按「无需授权」处理，功能照常可用。

### 上架前必须在后台填的《用户隐私保护指引》

微信公众平台 → 设置 → 服务内容声明 → **用户隐私保护指引**。
不填这里，小程序审核会被判定「未提供隐私政策」驳回。

建议勾选/填写的条目如下（这个项目只用得到前两项）：

| 信息类型 | 用途说明 | 当前版本 |
| --- | --- | --- |
| **用户填写的信息** | 你输入的昵称、日期与文字，仅保存在本机，用于生成本地纪念册图片；当你转发纪念册时，这些内容会附在你发出的转发消息里直接送达接收方，不经过开发者服务器 | 不在服务器留存 |
| **相册（仅写入）权限** | 把生成的纪念册图片保存到系统相册 | 仅在你点击「存到相册」时使用 |
| 剪切板 | 不收集 | 不使用 |
| 位置 / 手机号 / 微信好友 / 身份证号 | 不收集 | 不使用 |

「存到相册」只请求**写入**权限，不读取你相册里已有的任何照片。

## 上架（个人主体）

下面这条路是**个人主体 + 工具类**，不需要公司。完整清单见 [`上架清单.md`](上架清单.md)。

要点先说在这里：

- 个人主体可以注册小程序、做小程序备案，但**类目选择很窄**。`恋爱 / 情感 / 婚恋交友` 在个人主体下**基本选不到**。
- 所以你这个项目上架时，类目要选能过的那一类，**页面里的功能文案也要跟着它改**：
  - 推荐：**工具 → 效率** 或 **工具 → 信息查询**，官方描述写「本地文字记录与图片生成工具」
  - 可选：**生活服务 → 记事本 / 便签**
- 下列内容在上架前已经全部删除，请不要又加回来：任何形式的广告解锁、去水印、会员付费、双人互动，以及「假装完成了某个任务才能导出」的按钮。
- 一个小程序只能改名 2 次（一年内），名称里**不要**出现「恋爱」「情侣」「婚恋」这类词，不然提交审核或者后续被投诉都很麻烦。

## 数据存在哪里

存在微信（或开发者工具）的本地缓存里，两个键名：答案 `loveWrapped.answers.v1`，主题 `loveWrapped.theme.v1`（「清空这台设备上的答案」只删答案，配色保留）。

不会上传，没有账号，也没有云数据库。

清缓存的位置：开发者工具顶部「清缓存 → 清除数据缓存」。

## 这个项目里的文件

```
app.js              小程序入口
app.json            有哪些页面、窗口颜色、隐私检查开关
app.wxss            全局底色和按钮；其余主题的按钮覆盖
sitemap.json        微信要求的索引配置
project.config.json 开发者工具的项目配置
pages/index         填写页（含主题选择器）
pages/wrapped       滑动纪念册、导出与分享（dock 上有配色圆点）
utils/record.js     答案有哪些字段、日期怎么算
utils/sample.js     示例内容
utils/slides.js     答案怎么变成每一页的句子
utils/storage.js    读写本机缓存（答案和主题各一个键）
utils/geo.js        内置城市坐标库与直线距离推算（不联网）
utils/themes.js     四套主题的唯一定义源：色板、弥散底几何、样式串生成
utils/brand.js      产品名与分享文案的唯一出处
utils/gift.js       转发带来的纪念册：答案打包/解包进分享链接
utils/backup.js     把一册备份成一段可收藏的文字
utils/privacy.js    隐私授权检查
utils/poster.js     用画布把一页画成图片；也画分享卡片封面
```

想改纪念册上的句子，打开 `utils/slides.js`。想改产品名或转发文案，打开 `utils/brand.js`。

## 颜色与主题

四套主题（奶油 / 抹茶 / 晴蓝 / 雾紫）的色板、弥散底几何全部定义在 `utils/themes.js`：

- **屏幕上的弥散底和卡口细线**：由 `themes.js` 算成内联 style 直接挂在节点上
  （填写页的 `ambientMesh` / `ambientLower` / `ambientFade`，纪念册每页的
  `meshStyle` / `hairStyle`）。这样做是因为开发者工具里 swiper 内容对样式表的
  多级选择器级联不稳定，内联样式在工具和真机上都确定生效。
- **屏幕上其余的主题色**（标题字色、胶囊、落款、dock、进度条等）写在
  `pages/wrapped/wrapped.wxss` 和 `pages/index/index.wxss` 的 `.theme-xxx` 规则里。
- **导出图片**：`utils/poster.js` 从 `themes.js` 直接取色。
- **弥散底几何**（每摊的位置、大小、透明度）只有一份：`themes.js` 的
  `MESH_GEO`，屏幕和画布共用，只是画布的 alpha 单独一列。

改颜色 = 改 `themes.js`，再同步对应 `.theme-xxx` 的文字色；不用再像以前那样三处对表。

## 已知限制

- 没有服务器。换手机、删除小程序、清除缓存，答案都没了，不能从云端找回。
- 公里数是按内置城市坐标库（`utils/geo.js`）用直线推算的，全部带「≈」。库里收录了全部省会、常见城市、旅行地和常见国家；没收录的名字照常显示，只是不算距离。
- 开发者工具里「存到相册」经常失败。请用「预览」到手机上保存，或先点「查看大图」、长按保存。
- 整本是连贯的长图，按内容实际高度绘制。整本很长时为了不超过画布边长，会比单页稍模糊；单页导出是按屏幕清晰度画的。
- 分享卡片封面会印两个昵称和在一起的天数；答案也随卡片一起送达，对方点开直接看到整册。朋友圈转发不带答案（链接长度受限），点开仍是空白填写页。
- 天数按「开始当天为第 1 天」计算，同一份示例过几天再打开，封面天数会变。
- 不做登录、广场、支付、地图、星座，也没有双人互相答题。
- 个人主体可以发布上线，但个人主体的可用类目受限，付费与广告能力也需要满足额外条件。

## 常见问题

**导入后提示找不到 app.json。**  
目录选高了一层。重新导入，选中能直接看到 `app.json` 的文件夹。

**模拟器一片空白，调试器有红字。**  
把调试基础库调到 3.x，再编译。确认导入类型是小程序，不是小游戏。

**点了生成，却说还差必填项。**  
两个昵称和日期都要有。昵称如果只有空格，也会被当成没填。

**示例是 9 页，我只想要 6 页。**  
回到填写页，吵架选「先不写」并清空次数，距离选「先不写」，把一起去过的地方一块块点 × 删掉，再生成。底部会写「会生成 6 页」。

**导出图片是空白的。**  
先把基础库调到 3.0 以上。仍空白的话，用手机预览再试一次。

**改了句子但纪念册没变。**  
改的是 `utils/slides.js` 的话，保存文件后点「编译」。改的是填写内容的话，返回填写页再点一次「生成纪念册」。

**想用得意黑字体。**  
项目默认用手机自带字体（苹方、黑体、微软雅黑）。得意黑完整文件有几 MB，超过小程序主包上限，所以不放进项目。如果确实要用，需要自备 HTTPS 字体地址，在 `app.js` 里用 `wx.loadFontFace` 加载；正式版还需要把该域名配到小程序后台的 `downloadFile` 合法域名里，并且这个域名要你自己备案。不做这一步并不影响任何功能。
